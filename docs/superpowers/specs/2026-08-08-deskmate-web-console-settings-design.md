# DeskMate Web Console 设置中心设计

> 状态：设计方向已确认，等待书面规格评审；尚未进入实施。
>
> 日期：2026-08-08
>
> 关联设计：[番茄钟功能设计](2026-07-27-pomodoro-design.md)

## 1. 背景与结论

DeskMate 当前 Web Console 已经具备文件管理、系统状态和版本化 Settings Provider，但“设备管理”
页面仍按调试器思路组织：浏览器直接看到配置分区、原始字段和刷新/保存工具栏，单一番茄钟分区也
必须先经过分区选择。它能够工作，却不适合作为交付给普通设备用户的设置界面。

第一版采用“借用 iOS 设置的信息架构，但不复刻 iOS 外观”的混合方案：

```text
文件管理 | 设置

设置
├─ DeskSuite Hub
├─ 番茄钟
└─ 设备与系统
```

顶层只保留“文件管理”和“设置”。设置首页使用分组列表和当前值摘要，点击后进入最多一层详情页。
普通字段先形成浏览器草稿，由用户显式保存；Hub 连接测试使用独立的非破坏性设备动作，不伪装
成布尔值或普通设置字段。

本轮明确不加入 Wi-Fi 配置，也不建立独立“声音设置”。现有 Wi-Fi/Portal 流程、文件管理功能和
番茄钟完成音乐的 SD 卡 MP3 语义保持不变。

## 2. 用户、目标与体验方向

### 2.1 使用者

使用者是 DeskMate 的拥有者或家庭管理员。他通常就在设备旁边，通过设备屏幕获得 Web Console
访问码，再用同一局域网内的手机或电脑打开控制台。他的目标不是调试 Provider，而是快速确认
“现在是什么设置”“我改了什么”“设备是否真的保存成功”。

### 2.2 目标

- 从设置首页一次点击进入任一设置类别。
- 不要求用户理解 section、effect、version、request ID 或 NVS 等实现术语。
- 所有修改在离开前都有明确的未保存提示，保存结果与设备真实持久化结果一致。
- 手机和桌面使用同一套响应式页面；它不是只为手机设计的维护页。
- 页面仍适合 ESP32 内嵌资源：不加载外部字体、图标库或运行时框架。

### 2.3 视觉语言

- 领域词汇：专注、短休、长休、轮次、完成提醒、同步、设备、连接。
- 色彩世界：电子纸白、石墨黑、雾灰、DeskMate 蓝；绿色、琥珀色和红色只表达成功、警告和错误。
- 标志性元素：番茄钟入口和详情页始终显示可读的“节奏摘要”，例如
  `专注 25 分钟 · 短休 5 分钟 · 每 4 轮长休`。
- 字体：系统字体栈，优先使用设备已有字体；不通过网络下载字体。
- 表面：连续分组列表、细分隔线和轻微层级，不使用装饰渐变、厚边框、夸张阴影或卡片矩阵。

需要主动拒绝的默认方案：

| 默认做法 | 本设计替代方式 |
| --- | --- |
| 暴露“配置分区”下拉框 | 设置首页直接展示用户能理解的类别 |
| 每个字段做成相同卡片 | 使用连续分组行，按业务关系组织字段 |
| 所有数字使用普通文本框 | 使用可直接输入的步进器，并保留范围与步长 |
| 修改一个控件立即写设备 | 使用显式草稿、撤销和保存 |
| 用颜色装饰页面 | 颜色只表达选中、连接和结果状态 |

## 3. 范围

### 3.1 第一版包含

1. 将顶层“设备管理”改为“设置”，保留“文件管理”。
2. 新增设置首页和一层详情导航。
3. 新增 DeskSuite Hub 地址查看、连接测试和安全保存。
4. 重做番茄钟设置表单与保存状态机。
5. 将现有七项系统状态整理进“设备与系统”。
6. 扩展通用 Web Console 元数据和非破坏性动作契约，使共享组件不硬编码 DeskMate 产品名称。
7. 补充浏览器行为、Provider、持久化和 HTTP 契约测试。

### 3.2 第一版不包含

- Wi-Fi 搜索、SSID/密码编辑、Portal 接力或在线换网。
- 独立声音设置；完成音乐继续属于番茄钟。
- 全局音量、静音、提示音包或扬声器诊断。
- 文件管理页面重排、WebDAV、递归文件操作或公网访问。
- 多级设置搜索、账户体系、主题切换、远程云控制或多设备管理。
- 网页内 OTA 检查、安装或独立重启动作。当前 Web Console 租约会拒绝 OTA；这类动作需要单独
  设计 Console 交接和浏览器断开体验，不能夹带进本轮 UI 优化。
- 在网页中读取或回显 Wi-Fi 密码、设备 API Token、访问码或 Bearer Token。

## 4. 信息架构与导航

### 4.1 顶层导航

登录后顶部导航只有：

```text
[文件管理] [设置]                                      [退出登录]
```

- 文件管理沿用现有路由、操作和页面结构。
- 设置默认进入设置首页，不再同时把系统状态和通用表单纵向堆在同一页。
- 当前顶层入口使用文字、底色和 `aria-current` 三种方式共同标识。

### 4.2 设置首页

```text
设置
管理 DeskMate 的服务、专注节奏和设备状态

┌────────────────────────────────────────────┐
│ DeskSuite Hub                         ›     │
│ http://192.168.6.13:8765                    │
├────────────────────────────────────────────┤
│ 番茄钟                                ›     │
│ 专注 25 分钟 · 短休 5 分钟 · 每 4 轮长休   │
├────────────────────────────────────────────┤
│ 设备与系统                            ›     │
│ 固件 0.2.0 · 已运行 3 小时                  │
└────────────────────────────────────────────┘
```

首页摘要来自各领域公开快照，不在前端复制产品默认值。某一类读取失败时，仅该行显示“暂时无法读取”，
其余类别仍可进入。

### 4.3 详情导航

- 详情页标题左侧使用“设置”返回按钮，并保留清楚的当前页标题。
- 浏览器后退键与页面返回按钮行为一致。
- 从有未保存草稿的详情页返回设置首页、切换到文件管理、退出登录或关闭页面时，统一触发草稿保护。
- 第一版不允许详情页继续进入第三级设置。文件选择器属于番茄钟字段的临时选择界面，不算设置层级。

## 5. 页面设计

### 5.1 DeskSuite Hub

页面结构：

```text
‹ 设置                         DeskSuite Hub

连接状态
○ 尚未测试

服务器
Hub 地址
[ http://192.168.6.13:8765                    ]
设备将通过该地址获取天气、日历、邮件、额度和语音服务。

[测试连接]                                      [保存]
```

交互规则：

- 第一版接受 LAN `http://` URL；主机可以是 IPv4 地址或可解析的主机名。
- 地址只允许 scheme、host 和可选端口；拒绝用户信息、query、fragment 和业务路径。
- 保存时把 scheme 和 host 规范化为小写，移除唯一的末尾 `/`，并保留用户显式填写的端口。
- URL 作为 Hub 产品字段使用 ASCII，最大 127 字节，与现有 `network_cfg.service_url[128]`
  一致；该限制由 `app_network_hub_url_parse_copy()` 和产品所有者保证。通用 Provider 字符串值
  缓冲区显式扩展为 128 bytes（含终止 NUL），值使用有效 UTF-8 并受字段上限与全局 127 bytes
  上限共同约束，禁止 embedded NUL 和静默截断。
- “测试连接”由设备端对候选地址的 `/healthz` 发起有界请求，浏览器不直接跨域访问 Hub。
- 健康请求不携带设备 API Token，避免把凭据发送给尚未信任的候选地址。
- 测试不写入配置。地址变化后，旧的测试成功状态立即失效。
- “保存”会再次校验并测试同一候选，避免把过期的测试结果当成提交保证。
- 测试成功后，只替换现有网络配置中的 Hub URL；SSID、Wi-Fi 密码和设备 API Token 原样保留，
  且从不进入 HTTP 响应或日志。
- 候选配置先通过新的网络 Application 所有者命令完成单份 `network_cfg` blob 提交，成功后才
  形成新设置版本。不能复用会跨 OTA 与网络两个 namespace 分别提交的全量 `settings_store_save()`。
  测试或持久化失败时继续使用旧 URL。
- 网络 Application 是 Hub URL 快照、严格递增 version、单个 pending 请求和最终结果的唯一写入
  所有者；Web Console Provider 只做字段映射和异步请求转接。
- 成功保存后，新 URL 从下一次 Dashboard、OTA 或语音事务开始生效；已经在途的事务继续使用其
  原快照，不要求重启设备或断开网页。网络所有者随后以最佳努力重新配置缓存后端上下文的远程
  日志客户端；该步骤失败不回滚已提交 URL，并在下次网络会话建立时重试。
- `/healthz` 是 Hub 侧跨项目先决契约。当前工作区存在尚未提交的实现时，也不能把它当作已落库、
  已部署能力；设备功能验收前必须先确认目标 Ubuntu Hub 的该路由可用。

连接结果使用客户语言：

| 事实 | 页面文案 |
| --- | --- |
| URL 语法错误 | “请输入完整的 Hub 地址，例如 http://192.168.6.13:8765” |
| DNS/连接失败 | “设备无法连接该地址，请检查地址和局域网” |
| `/healthz` 非 2xx 或 JSON `status` 不是 `ok` | “已连接服务器，但健康检查未通过” |
| 超时 | “连接测试超时，原设置未更改” |
| 持久化失败 | “服务器地址未保存，设备仍使用原地址” |

### 5.2 番茄钟

页面结构：

```text
‹ 设置                              番茄钟

专注 25 分钟 · 短休 5 分钟
每 4 轮进入 15 分钟长休

专注与休息
专注时长                         [−] 25 [+] 分钟
短休时长                         [−]  5 [+] 分钟
长休时长                         [−] 15 [+] 分钟
长休间隔                         [−]  4 [+] 轮

完成提醒
完成音乐                           complete.mp3
/music/complete.mp3                          [更换音乐]

已修改 2 项                         [撤销] [保存]
```

字段规则沿用所有者当前约束，不在前端另建第二份规则：

| 字段 | 范围 | 步长 |
| --- | ---: | ---: |
| 专注时长 | 5–90 分钟 | 5 |
| 短休时长 | 1–30 分钟 | 1 |
| 长休时长 | 5–60 分钟 | 5 |
| 长休间隔 | 2–8 轮 | 1 |

- 步进器的数字仍可直接输入，键盘、触摸和辅助技术都能操作。
- 完成音乐只允许通过现有 Files 能力选择 `.mp3` 逻辑路径；主行显示文件名，完整路径作为次要信息。
- Files 能力被裁剪时，保留当前路径只读展示，不显示不可用的选择按钮。
- 番茄钟非 `IDLE` 时，字段保持可读但不可修改，并说明“结束当前番茄钟后可修改”。
- 页面不建立独立声音类别，也不改变 Audio Service 或 SD 卡 MP3 播放链路。

保存必须是持久化原子事务：所有者在执行点重新校验状态和版本，先在锁外写入候选 NVS，再在短锁内
同时公开新设置、新版本和成功结果。NVS 失败时旧设置和旧版本都保持不变，不能出现“页面说失败，
运行时却已经改了”的状态。

### 5.3 设备与系统

页面结构：

```text
‹ 设置                           设备与系统

关于本机
固件版本                              0.2.0
构建时间                    2026-08-08 10:20
运行时长                        3 小时 12 分
上次重启原因                         软件重启

资源
可用 SRAM                           182 KiB
可用 PSRAM                         6120 KiB
CPU                                    240 MHz

```

- 秒数、KiB 和 MHz 等原始事实由前端转成适合阅读的格式，原值仍来自 System 所有者快照。
- 第一版只呈现当前已有的固件版本、构建时间、运行秒数、SRAM、PSRAM、CPU 频率和重启原因，
  不臆造 device ID、联网诊断或更新状态。
- 该页是设置中心内的只读设备信息页，不为了目录对称添加空 Settings Provider。

### 5.4 OTA 与重启的后续边界

当前 `app_network` 在请求入口和执行点都会拒绝任何活动网络租约下的 OTA，而 Web Console 运行时
持有专用租约。因此第一版不显示无法在当前会话中可靠完成的“检查更新”“安装”或“重启”按钮。

未来若单独立项，默认采用可解释的交接流程：先向浏览器说明即将断开并发送接受响应，再停止
Console、释放租约，最后提交 OTA 或重启；不能只删除租约检查强行共存。是否重新开放 Console、
如何让用户取得新访问码和查看 OTA 结果，必须在该独立设计中确认。

## 6. 通用前端状态机

每个设置详情页独立维护以下状态：

| 状态 | 含义与界面行为 |
| --- | --- |
| `loading` | 显示骨架或短文本，禁止提交 |
| `synced` | 浏览器草稿与设备快照一致 |
| `dirty` | 显示修改数量，启用撤销和保存 |
| `saving` | 锁定当前表单，显示提交/等待结果进度 |
| `succeeded` | 重新读取权威快照后显示保存成功 |
| `validation_error` | 保留草稿并在对应字段附近显示错误 |
| `owner_busy` | 保留草稿，说明当前业务状态不允许修改 |
| `network_unknown` | 请求结果未知，不盲目重复提交，允许继续查询原请求 |
| `version_conflict` | 保留草稿并读取设备新版本，由用户确认后重新应用 |
| `session_expired` | 停止轮询，保留非秘密草稿，并返回登录页 |

### 6.1 草稿保护

- 首次修改后进入 `dirty`，保存按钮显示修改项数量。
- “撤销”恢复最近一次成功读取的设备快照。
- 离开当前详情时，提示“保存更改 / 放弃更改 / 继续编辑”。
- `beforeunload` 只能使用浏览器原生确认；页面内导航使用自有确认层。
- 冲突不能自动重新读取并丢弃草稿。新设备版本与本地草稿同时保留，用户再次确认后才以新版本为
  基线提交。

### 6.2 异步结果

继续沿用现有可靠主链路：

```text
GET 权威快照和 version
    → 用户编辑本地草稿
    → PATCH(expectedVersion, changes)
    → 取得 requestId
    → 有界轮询结果
    → 成功后重新 GET 权威快照
```

- 轮询必须有总期限和退避，不能无限循环。
- 非秘密的 section、request ID 和开始时间可以暂存在 `sessionStorage`，同一登录会话恢复后继续查询。
- 请求超时不等同于失败；页面进入 `network_unknown`，避免重复动作造成二次写入。
- 终态返回稳定原因，例如 `version_conflict`、`owner_busy`、`persistence_failed`、
  `connection_failed`。前端映射客户文案；日志保留中文技术事实，但不泄漏凭据。

## 7. 共享组件与产品边界

### 7.1 页面类别不是新的业务所有者

“DeskSuite Hub”“番茄钟”“设备与系统”只是浏览器信息架构，不等同于三个 Settings Provider。
同一详情页可以组合：

- Settings：可编辑、带 version 的领域设置。
- Status：只读领域事实。
- Actions：有异步结果的非破坏性设备动作；第一版仅用于 Hub 连接测试。

共享 `web_console_service` 只负责认证后的 HTTP 映射、元数据、固定路由、结果分发和网页渲染；
领域 Application 继续拥有校验、排队、持久化、生效和失败策略；未纳入第一版的 OTA、重启也
始终保留在产品 Application/工具所有者，而不是下沉到 HTTP handler。

### 7.2 最小元数据扩展

通用 Provider 元数据增加足够表达客户界面的可选信息：

- section 的稳定 ID、标题和简短说明。
- 字段说明、独立单位和“可用于首页摘要”的呈现标记。
- 非破坏性 Action 的稳定 ID、标题和异步结果入口。

Settings、Status 和 Actions 使用相同 section ID 时，前端把它们组合成同一详情页；不同 Provider
仍保持独立生命周期和所有权。共享代码不得按 `pomodoro`、`hub` 或 `system` 写产品条件分支。

不为视觉目录增加空 Service、Task 或一对一 Provider；也不把动态产品摘要模板硬编码进通用
JavaScript。首页摘要由被标记的公开字段经过通用单位格式化得到。

### 7.3 Action 契约

为 Hub 连接测试新增最小、可裁剪的非破坏性 Action Provider：

```text
认证 POST 动作
    → Core 完成通用格式和权限校验
    → 产品 Provider 复制请求并交给 Application
    → 返回 request ID
    → 可轮询动作读取所有者结果
```

- `Action` 在本规格中只是 HTTP/界面类别，不预先冻结新的 C 公共术语。实施前必须优先使用现有
  受控 `request` / `result` 语义；若公共类型仍需要 `action`，应在同一任务先补充受控术语并说明边界。
- HTTPD Task 不执行 Hub 探测、OTA 下载、持久化或重启。
- Action Provider 不持有 Application 的 Task、Queue 或网络租约。
- Actions 构建开关关闭时，不编译路由、Provider 注册和对应网页代码。
- 所有动作路由继续使用现有 Bearer 会话、`Cache-Control: no-store` 和活动 handler 停止屏障。

### 7.4 必须同步的契约文档

实施会改变当前“状态在前、设置在后组成设备管理页”的既有目标描述，因此必须同步：

- `devices/deskmate/docs/architecture/web_console_service.md`
- `shared/components/services/web_console_service/README.md`
- `devices/deskmate/main/application/README.md`
- 新增或实质修改的 Application/Service 公共头文件 Doxygen

文档只记录最终实现的事实，不把尚未落地的可选方案写成既成能力。

## 8. 响应式、可访问性与资源约束

### 8.1 响应式布局

- 桌面正文宽度控制在约 680–760 px，避免设置行横跨整屏。
- 手机宽度下保持单列；主要触摸目标最小 44 px，高频保存操作使用底部粘性操作栏。
- 设置首页的三个入口应在 390×844 视口首屏内可见；不让系统状态块把真正设置推到首屏之外。
- 桌面键盘焦点、手机软键盘和安全区域不能遮挡错误提示或保存栏。

### 8.2 可访问性

- 所有输入都有真实 `label`；辅助文字使用可关联的描述 ID。
- 状态不能只靠颜色，必须同时有文字或图形符号。
- 异步结果使用克制的 `aria-live`，避免每次轮询都重复播报。
- 确认层锁定焦点，关闭后返回触发按钮；Escape 可取消非强制操作。
- 支持 `prefers-reduced-motion`，过渡只用于表达页面和状态切换。

### 8.3 嵌入资源

- 不引入框架、外部字体、远程图片或大型图标包。
- 继续由现有构建脚本确定性组装并 gzip 压缩启用模块。
- 实施时记录修改前后完整组合的 gzip 字节数；若增量超过 25%，必须先收敛重复 CSS/JS，再评估
  是否接受，而不是静默扩大固件资源。
- 所有裁剪组合继续可生成；Actions 加入后测试矩阵必须覆盖开关打开和关闭。

## 9. 错误与安全边界

- 页面只展示可操作的客户文案，内部 `esp_err_t` 可作为日志事实，但不能直接成为主要页面文本。
- 客户端校验只用于即时反馈；Provider 和领域所有者必须再次校验。
- 任一设置更新失败都保留旧的持久化权威值；不能只回滚页面而留下运行时新值。
- Hub 健康检查只证明指定进程可达，不证明全部外部 AI、天气或邮件依赖可用。
- 登录过期、页面关闭和轮询取消不取消已经被 Application 接受的动作。
- 访问码、Bearer Token、Wi-Fi 密码和设备 API Token 不进入页面草稿、`sessionStorage`、日志或
  错误正文。
- Hub 测试拒绝与同一 section 的保存并发；新的设备动作必须等待当前动作形成终态。

## 10. 验证策略

### 10.1 共享组件

- Provider 注册测试：section 合并、说明/单位/摘要标记、UTF-8 和长度边界、重复 ID、非法 Action。
- HTTP 测试：未认证、过期会话、错误 Content-Type、超限正文、动作提交和结果轮询。
- 构建资源测试：所有 Files/Settings/Status/Actions 裁剪组合、确定性 gzip、无 `.innerHTML` 回归。
- JavaScript 行为测试：路由、浏览器后退、草稿保护、冲突保留、有界轮询和会话过期。

### 10.2 DeskMate 产品

- Hub：URL 规范化、非法 URL、健康成功/失败/超时、只更新 URL、秘密保持、持久化失败不发布新版本，
  以及远程日志重新配置失败不回滚已提交 URL。
- 番茄钟：范围/步长、非 `IDLE` 拒绝、版本冲突、NVS 成功后发布、NVS 失败保持旧内存值和旧版本。
- 系统：单位格式化所需字段完整；状态读取单项失败不阻断设置首页。
- Actions：Hub 测试的重复请求、并发互斥、有界超时和结果未知恢复。
- 既有产品 Provider 静态检查随元数据和 Actions 契约同步更新；其中强制“先发布内存、再写 NVS”
  的旧顺序断言必须反转。

### 10.3 浏览器与实机

- 在 1440×900 和 390×844 两种视口验证设置首页、三个详情页、键盘焦点和粘性保存栏。
- 使用模拟 API 覆盖 loading、dirty、saving、success、field error、busy、conflict、unknown 和
  session expired。
- 实机验证访问码登录、Files 回归、番茄钟 MP3 选择、Hub 成功/失败保存、新 URL 在下一事务生效，
  以及远程日志后端被重新配置。
- 固件编译仍只能从 DeskSuite 根目录通过 `ds.ps1` 执行，并遵守项目“用户明确要求后才编译”的
  规则。

## 11. 验收条件

1. 登录后顶层只有“文件管理”和“设置”，Files 行为无回归。
2. 设置首页只展示 `DeskSuite Hub`、`番茄钟`、`设备与系统` 三个客户入口，并能一次点击进入。
3. 页面不出现“配置分区”、`idle_only`、request ID、NVS 等实现术语。
4. Wi-Fi 配置和独立声音页未被引入；番茄钟完成音乐仍选择 SD 卡 `.mp3`。
5. 390×844 首屏可以看到三个设置入口，详情页保存栏不会遮挡最后一个字段。
6. 任一未保存草稿在返回、切换 Files、退出和关闭页面前得到保护；版本冲突不会清空草稿。
7. 番茄钟步进器遵守 Provider 范围和步长，非 `IDLE` 时清楚解释只读原因。
8. 番茄钟持久化失败时运行时设置和 version 均不改变，页面报告失败。
9. Hub 测试不修改配置；保存会重新测试，失败保留旧 URL，成功只替换 URL，并从下一事务开始
   生效且无需重启。
10. 页面和接口从不返回或记录 Wi-Fi 密码、设备 API Token、访问码或 Bearer Token。
11. “设备与系统”以客户格式展示现有七项系统事实，不出现当前会话无法可靠完成的更新或重启按钮。
12. 所有轮询有总期限；网络结果未知时不自动重复写入或重复动作。
13. 共享组件没有 DeskMate 产品 ID 条件分支，关闭可选模块后对应代码和网页资源不进入固件。
14. 共享组件测试、DeskMate 产品静态检查、浏览器测试均通过；固件编译和实机验收分别报告。

## 12. 实施顺序边界

书面规格确认后，实施计划应按以下可独立验证的顺序拆分，但本文件不直接授权开始编码：

1. 共享页面信息架构、元数据和前端草稿状态机。
2. 最小 Action Provider 及其 HTTP/裁剪契约。
3. DeskMate 番茄钟原子持久化修正与客户字段元数据。
4. Hub URL Provider、设备端健康检查与安全持久化。
5. 系统状态客户格式化与跨项目 Hub 健康契约核验。
6. 浏览器、静态、固件与实机分级验证。

每一步只提交自身文件和代码块，保留工作区内现有 Hub 等无关修改。
