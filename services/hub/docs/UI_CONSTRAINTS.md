# PhotoPainter 墨水屏 UI 设计规范

本文档是 PhotoPainter 显示页面的唯一 UI 规范，适用于 `web/pages/<page-id>/` 下的 HTML、CSS、JavaScript，以及所有会进入设备最终画面的字体、图标和图片。

设计目标不是模拟普通网页，而是在固定的 `800×480` 四灰阶墨水屏上，让人隔一段距离也能在几秒内看懂最重要的信息。

本文档只定义通用设计与实现约束，不规定、描述或示范任何具体页面、业务模块和数据内容。

文档中的关键词含义：

- **必须**：所有页面都要遵守；不满足即视为设计缺陷。
- **默认**：没有明确业务理由时必须采用。
- **允许**：仅限条目中写明的场景。

## 1. 核心原则：简洁、直接、铺满

### 必须

- 每个页面只能有一个第一视觉重点。
- 主信息必须一眼可见，不能依赖滚动、点击、悬浮、动画或翻页才能理解。
- 每一段文字和每一个图形都要回答一个问题：删掉它是否会影响用户理解或行动？如果不会，就删除。
- 信息层级最多三层：主信息、必要的辅助信息、异常状态。不得为了“看起来完整”增加第四层装饰性信息。
- 版面应充分使用扣除安全边距后的全部宽高。主图、核心数字、列表或图表应主动放大，避免把内容缩在画面中央。
- “铺满画布”指内容布局占满可用空间，不代表使用大面积黑色背景。

### 默认删除

以下内容默认不进入设备画面：

- 通用顶部栏和底部栏。
- 页面自带的当前日期、星期和时间。
- “数据来源”、供应商名称、品牌标识和接口名称。
- 右下角“更新于”“最后同步”“缓存数据”等刷新信息。
- 中英文重复标签。
- 仅用于装饰的副标题、口号、图标、边框和标签。
- 用户已经能从页面内容判断出的标题。

数据来源、更新时间和缓存状态仍可保留在服务端日志、接口响应或管理界面中，但不占用墨水屏空间。

### 允许例外

- 日期本身是核心数据时可以显示，但不得再额外创建一条通用日期栏。
- 地点会改变数据含义时可以显示，只保留最短且可区分的中文地点。
- 数据时效性直接影响决策时可以显示更新时间；使用简短中文，并放在对应内容附近，不创建固定页脚。

## 2. 画布与空间使用

### 固定画布

- 页面尺寸固定为 `800×480px`，截图使用 `deviceScaleFactor = 1`。
- `html`、`body` 和页面根节点必须占满 `800×480px`，并设置 `overflow: hidden`。
- 禁止响应式断点、滚动条、浏览器缩放和 `transform: scale()` 整页缩放。
- 所有关键坐标和尺寸使用整数像素，禁止 `0.5px` 线条和由百分比计算出的模糊小数位置。

### 空间分配

- 页面外边距默认为 `0`，主布局必须从画布边缘开始并占满 `800×480px`。
- 分区优先使用共享分隔线；分隔线应连续延伸到相邻分区或画布边缘，不在其外侧保留装饰性空隙。
- 相邻分区默认不使用间距，不为每个分区重复绘制完整外框；使用一条共享边线表达一次分隔关系。
- 文字、图标和数据必须在所属分区内部保留 `8–12px` 安全间距，不得紧贴物理屏幕边缘或分隔线。
- 页面主布局必须同时填满全部宽度和高度，不为已删除的结构预留空行。
- 只有信息确实需要分组时才划分区域。避免“每个数字一个框”、多层嵌套和重复边框。
- 页面一般使用 `2–4` 个主要信息区域；列表型页面可以有更多重复行，但视觉上仍应属于一个主区域。
- 大块空白必须用于强调主信息或分隔信息。若空白没有明确作用，应放大主图、数字、列表行高或图表。

### 内容尺寸建议

- 单一主图建议使用约 `220–320px` 的视觉尺寸。
- 核心数字建议使用 `48–96px` 字号。
- 列表应尽量使用完整可用高度，通过合理的行高提高远距离可读性，而不是在底部留下空白。
- 固定布局必须为最长合理数据预留空间，包括极值、负数、较长中文名称和固定格式时间。

## 3. 四灰阶规范

最终设备帧为 `PPF2 / GRAY2`，每个像素只能是以下四个灰阶。页面不得自行定义第五种视觉颜色。

| 灰阶 | CSS 色值 | GRAY2 | 可以使用 | 不能使用 |
|---|---|---:|---|---|
| 黑 | `#000000` | `0` | 主文字、核心数字、重要图标、关键边框、主数据线、局部反白底 | 大面积整屏背景、无意义装饰块 |
| 深灰 | `#555555` | `1` | 白底上的次要文字、次级数据线、辅助图形 | 核心信息、告警、黑底文字、低于 `14px` 的中文 |
| 浅灰 | `#AAAAAA` | `2` | 大块辅助底色、非关键分区、参考线、不可用占位区域 | 正文、细小图标、关键状态、白底上的文字 |
| 白 | `#FFFFFF` | `3` | 页面主背景、卡片背景、黑底上的局部反白文字 | 浅灰底上的文字、依赖白色轮廓区分的复杂图形 |

### 安全文字组合

可见文字只使用以下组合：

- 黑字配白底：默认正文和数字。
- 黑字配浅灰底：辅助区域。
- 深灰字配白底：字号不小于 `14px` 的次要信息。
- 白字配黑底：仅用于面积较小的重点标签或状态。

禁止浅灰字配白底、深灰字配黑底、白字配浅灰底，以及任何依赖细微灰阶差异才能看清的文字。

### 灰阶使用要求

- 关键内容必须主要依靠黑白高对比表达；深灰和浅灰只建立辅助层次。
- 状态差异必须同时通过中文文字、形状、边框、线型或填充表达，不能只靠灰阶。
- 文字型 UI 页面默认关闭抖动，直接使用四个目标色值。
- 禁止渐变、透明度、`rgba()` 半透明叠层、模糊、发光、阴影、玻璃效果、纹理背景和抗锯齿模拟灰色。
- 避免整屏反白和大面积纯黑。局部主图允许使用实心黑，但要检查残影，并避免刷新时大范围移动或黑白反转。
- 最终量化 PNG 必须只包含 `(0,0,0)`、`(85,85,85)`、`(170,170,170)`、`(255,255,255)` 四种 RGB 像素。

### 照片例外

- 只有照片本身是页面核心内容时，才允许开启 Floyd–Steinberg 抖动。
- 抖动照片不得作为文字背景，文字区域必须回到稳定的纯黑、纯白或浅灰色块。
- 图标、图表和其他信息型页面不得用抖动制造额外灰阶。

## 4. 中文优先与文字排版

### 语言

- 页面默认语言为简体中文，HTML 使用 `lang="zh-CN"`。
- 可见标题、标签、状态、错误提示和无障碍说明优先使用中文。
- 能用中文表达时不得保留英文副标签。
- 允许保留用户普遍认识且更短的行业标准缩写、法定计量单位或专有名词。
- 数据供应商、内部接口名、模板名和调试状态不属于用户信息，默认不显示。
- 一个页面同时出现的英文缩写应尽量不超过三个；英文不能成为主要视觉风格。

### 字体与字号

- 中文统一使用项目内的 Alibaba PuHuiTi 3.0，不依赖系统字体、在线字体或 CDN。
- 含中文的 TRMNL 文字角色同时使用 `.pp-cn`；最小字号内容使用 `.pp-cn-min`。
- 任何包含中文的可见文字不得小于 `12px`。
- `12px` 中文使用至少 `700` 字重，行高不得小于 `15px`。
- 普通正文建议 `14–20px`，区块标题建议 `20–32px`，核心数字建议 `48–96px`。
- 一个信息区域最多使用三个字号层级，整页字号、字重和对齐方式应保持稳定。
- 禁止极细字重、斜体、描边字、阴影字、半透明文字和过大的字间距。
- 纯数字可以使用数字宽度稳定的字体；不得因此让同一行中文字体发生变化。

### 文本长度

- 标签尽量使用 `2–6` 个汉字。
- 单行动态内容必须定义截断策略，禁止撑开固定布局。
- 多行摘要必须规定最大行数和固定高度；超过后截断，不缩小中文字号。
- 数据缺失使用“--”“暂无数据”或“数据不可用”，不要显示内部错误详情。

## 5. 线条、卡片、图标与图表

### 线条和卡片

- 关键边框和分隔线不小于 `2px`；主要数据线建议使用 `3px`。
- `1px` 只允许用于长距离参考线或非关键表格分隔，不能承载状态。
- 页面只使用一种主要边框粗细和一种强调粗细，避免无规则混用。
- 默认使用直角或很小的圆角，不使用胶囊卡片、大圆角和纯装饰外框。
- 不使用阴影营造层级；通过留白、对齐、黑白填充和少量浅灰底分区。

### 图标和主图

- 使用本地、受信任的 SVG，禁止 Emoji、在线图标和运行时网络图片。
- 普通图标不小于 `24×24px`，关键笔画在最终尺寸下不小于 `2px`。
- 图标应以轮廓和形状表达含义，不能只依赖内部灰阶。
- 主图是核心信息时应主动放大；主图只是装饰时应删除。
- 资源缺失时提供简短中文回退文本。

### 图表

- 图表必须在无颜色、无交互的情况下直接可读。
- 关键值直接标在数据旁，不能依赖悬浮提示或复杂图例。
- 同一图表建议不超过两条数据线；用实线/虚线、圆点/方点和中文标签区分。
- 主线使用 `3px`，次线至少 `2px`，数据点不小于 `8px`。
- 禁止半透明面积图、渐变图例、密集网格和依赖灰阶区间的热力图。

## 6. 数据、异常与刷新

- 页面只显示用户需要的数据，不显示接口健康状态、缓存命中、请求时间和调试信息。
- 单个数据源失败不能导致白屏或布局塌缩；在原信息位置显示简短中文状态。
- 不显示秒级时间，不展示无决策价值的分钟级变化。
- 禁止 CSS 动画、闪烁、跑马灯、自动轮播和连续变化的时钟。
- 动态数据要先格式化成适合设备阅读的中文短文本，再写入 DOM。
- 外部数据使用 `textContent`；只有服务端固定并校验过的本地 SVG 可以使用 `innerHTML`。
- 页面完成静态 DOM 和 SVG 后必须设置 `window.__PHOTO_PAINTER_READY__ = true`。

## 7. 页面实现边界

- 新页面使用 TRMNL 的 `screen--og`、`screen--2bit`、`screen--no-bleed`、`view--full` 和 `layout` 骨架。
- `web/shared/epaper.css` 统一维护画布、四灰阶、中文最小字号、线宽和禁用动画等设备约束。
- 页面 CSS 只定义当前页面特有的信息布局，不重复声明基础画布、色板和公共字体规则。
- 字体、CSS、JavaScript、图标和框架资源全部保存在项目内；渲染期间禁止外部网络请求。
- 字体加载完成后才能截图，所有影响像素的本地资源都必须参与页面静态指纹。

## 8. 交付检查清单

新增或修改页面时至少检查：

- [ ] 最终画面固定为 `800×480`，没有滚动、缩放、裁切和画布外内容。
- [ ] 页面只有一个明确的第一视觉重点，外边距为 `0`，主布局占满整个画布。
- [ ] 分隔线延伸到相邻分区或画布边缘，相邻分区没有装饰性间隙和重复外框。
- [ ] 文字、图标和数据在所属分区内部保留 `8–12px` 安全间距。
- [ ] 没有无必要的顶部栏、底部栏、当前日期、数据来源、供应商名称和更新时间。
- [ ] 可见文案默认使用简体中文，没有重复中英文标签。
- [ ] 所有中文不小于 `12px`，主信息尺寸足以远距离阅读。
- [ ] 页面只直接使用黑、深灰、浅灰、白四个目标色值。
- [ ] 关键文字采用安全的前景/背景组合，不依赖浅灰低对比文字。
- [ ] 信息型页面关闭抖动，没有渐变、透明度、阴影、模糊和纹理背景。
- [ ] 关键边框、图标笔画和数据线在 GRAY2 预览中连续清晰。
- [ ] 长中文、空数据和异常状态不会改变布局尺寸。
- [ ] 页面不依赖动画、交互、在线资源或 Emoji。
- [ ] 生成的量化 PNG 只有四个规定 RGB 灰阶，并在目标墨水屏检查过小字、反白和残影。

当空间不足时，处理顺序必须是：删除非核心内容、缩短中文标签、合并重复信息、调整布局、拆成独立页面。不得通过缩小中文字体、减细线条或增加英文缩写来强行塞入内容。
