# DeskMate Timer 维护刷新 Light-sleep 流程

> 当前状态：设备在 60 秒无按键活动后进入 Light-sleep。左右键恢复网络与正常交互；
> ESP32 内部 Timer 每 60 秒唤醒一次，服务端截止时间到达时联网同步 Dashboard，随后停网、
> 刷新屏幕并继续睡眠。低功耗流程不读写 SD 卡。

## 1. 当前边界

- Light-sleep 不复位芯片；唤醒后从 `esp_light_sleep_start()` 的下一条语句继续执行。
- 左键 GPIO18、右键 GPIO0 通过 EXT1 低电平唤醒。
- ESP32 内部 Timer 是维护唤醒源，屏幕维护间隔默认 60 秒；服务端截止时间更近时缩短本轮
  间隔，使联网维护尽量对齐计划整点。
- RTC INT GPIO15 不参与轻睡眠唤醒，也不重置无活动窗口。
- 当前对 UI Runtime、显示传输和完整网络链路执行可逆 `stop/start`。
- 网络停止由 `app_network` 串行关闭产品 Timer、远端日志、Network Manager 和 Wi-Fi Driver；
  恢复只重启连接策略，需要联网维护时再同步等待 Dashboard 完成。
- 清醒态的 Dashboard 一次性 Timer 与 Light-sleep 联网维护共用服务端
  `next_refresh_at_utc`；本地失败退避只用于完整同步失败后的恢复，不参与正常刷新计划。
- 环境、按键扫描、音频、RTC Service 和 SD 卡尚未增加独立低功耗生命周期；Button Service
  保持 RUNNING，不在睡前 `stop()`、唤醒后 `start()`。
- WakeNet 常驻监听启用时自动 Light-sleep 关闭，因为 CPU 睡眠时不能处理麦克风数据。

内部 Timer 是 ESP32 睡眠控制器的硬件唤醒源，不是 FreeRTOS 软件 Timer。CPU 进入
Light-sleep 后普通 Task 不运行；到达设定间隔时，睡眠控制器恢复 CPU，原 Task 继续执行。

## 2. 职责分层

| 层级 | 组件 | 当前职责 |
| --- | --- | --- |
| Application | `main/application/app_power_task.c` | 60 秒活动窗口、阻止条件、截止时间到期判断、UI/网络顺序、计数和失败终态 |
| Application | `main/application/app_network_task.c` | 网络可逆暂停/恢复、同步维护回执及最近 `next_refresh_at_utc` |
| UI Runtime | `main/ui` | 可逆停止、Presenter 重同步和恢复刷新 |
| Graphics | `components/graphics/ui_platform` | 停止 LVGL/显示提交；恢复时同步完成一次完整显示传输 |
| Device | `components/device/device_power` | 转发一次带 Timer 间隔的同步睡眠事务，不拥有周期策略 |
| BSP | `components/bsp/src/bsp_power.c` | 配置/清理按键 EXT1 与内部 Timer，进入睡眠并锁存唤醒来源 |

SD 卡仍可被其他产品能力使用，但不再是 `app_power` 的依赖，也不再决定设备能否睡眠。

## 3. 主流程

```text
按键活动
    → app_power_notify_activity()
    → 重新开始 60 秒活动窗口

活动窗口到期
    → 检查语音 / 音频 / OTA / 网络租约
    → ui_runtime_stop()
    → app_network_suspend_for_light_sleep()
    → Device / BSP 配置左右键 EXT1 + min(60 秒, 距服务端截止时间) 内部 Timer
    → esp_light_sleep_start()
```

UI `stop()` 关闭业务入口、停止 LVGL tick 与新帧提交、等待显示 DMA 静止，并保留控件树、
字体、绘制缓冲、显示 Task、SPI 和面板控制器。

网络 `stop()` 停止 Dashboard/OTA/重连/校时 Timer 和远端日志，再同步停止 Network Manager
及 Wi-Fi Driver。任一步失败都会回滚到清醒态，不会在网络状态不明时继续睡眠。

## 4. 两类唤醒

### 4.1 Timer 维护唤醒

```text
内部 Timer 到期
    → 锁存 APP_POWER_WAKEUP_TIMER
    → 可信 UTC >= next_refresh_at_utc？
        → 是：恢复网络 → 同步 Dashboard → 保存新截止时间 → 再次停网
        → 否：网络保持停止
    → ui_runtime_start()
    → 从 Presenter 重新读取状态栏和当前页面
    → 同步提交完整刷新并等待显示 DMA 完成
    → timer_refresh_count++
    → 检查停止请求、新按键活动和产品阻止条件
    → 条件仍允许时再次 ui_runtime_stop()
    → 重新配置下一次屏幕/联网维护 Timer 并继续 Light-sleep
```

Timer 维护唤醒不会修改 `s_last_activity_us`，因此不会人为开启新的 60 秒交互窗口。没有
成功解析截止时间或系统 UTC 尚不可信时按“已到期”处理，借助本次联网同步取得可信时间和新
截止时间。Dashboard 同步失败保留旧截止时间，安全停网后在下一分钟重试。若刷新期间出现
按键活动，或语音、音频、OTA、网络租约开始占用，网络与 UI 保持运行并返回正常清醒流程。

### 4.2 左右键交互唤醒

左右键命中 EXT1 后，流程先恢复网络连接策略，再恢复 UI 并等待画面刷新完成，然后增加 `success_count`、
更新最后活动时间，重新开始 60 秒清醒窗口。若按键与 Timer 同时命中，按键语义优先。

睡眠期间 CPU 不执行普通 GPIO ISR，不能依赖睡眠中的按键边沿在唤醒后重放。BSP 因此按值返回
EXT1 左右键事实，Application 在 UI 恢复后显式桥接：

```text
EXT1 左右键掩码
    → app_power 恢复网络与 UI
    → button_service_request_light_sleep_wakeup_copy()
    → 持续按住：原 Device 状态机判定短按/长按
    → 快速释放：Button Service 重放一次短按
```

左右键事实可以同时提交；Button Service 将 EXT1 事实、GPIO 边沿和 Device 事件合并，同一实体键
最多产生一个产品事件。只有唤醒事实提交成功后，`app_power` 才增加 `success_count`。

GPIO0 是 ESP32-S3 启动配置引脚。Light-sleep 唤醒不发生复位，因此运行期可安全作为唤醒源；
上电或硬复位时仍不得一直按住右键。

## 5. 状态与错误

`app_power_get_status_copy()` 提供以下关键事实：

- `cycle_id`：每次物理 Light-sleep 尝试编号；
- `state` / `step`：当前主状态和显式步骤；
- `wakeup_source`：最近一次按键或 Timer 唤醒来源；
- `success_count`：按键唤醒并恢复交互次数；
- `timer_refresh_count`：Timer 唤醒并完成屏幕刷新次数；
- `primary_error`：睡眠、UI 停止或网络停止主流程错误；
- `recovery_error`：网络或 UI 恢复错误。

按键尚未释放或准备期间出现新活动属于暂时取消，网络和 UI 恢复后等待下一次机会。未知唤醒
来源、睡眠配置失败、网络/UI 无法停止或恢复会进入 `BLOCKED`，禁止继续自动睡眠。Dashboard
同步失败只保留旧数据并按分钟重试，不进入 `BLOCKED`。SD 卡错误不会进入
这条错误链。`button_service_request_light_sleep_wakeup_copy()` 提交失败同样属于恢复错误，
保存在 `recovery_error` 后进入 `BLOCKED`，禁止继续自动睡眠。

完成 100 次实机 Light Sleep 验收前，不增加 Button Service 睡前 `stop()` / 醒后
`start()`。该生命周期调整保留为后续独立阶段。

## 6. 配置

| Kconfig | 默认值 | 含义 |
| --- | --- | --- |
| `DESKMATE_LIGHT_SLEEP_ENABLED` | `y` | 启用按键与内部 Timer Light-sleep |
| `DESKMATE_LIGHT_SLEEP_IDLE_TIMEOUT_SEC` | `60` | 最后一次按键活动后的清醒窗口 |
| `DESKMATE_LIGHT_SLEEP_REFRESH_INTERVAL_SEC` | `60` | Timer 维护唤醒与屏幕刷新间隔 |
| `DESKMATE_LIGHT_SLEEP_RETRY_DELAY_MS` | `10000` | 暂时不可睡眠时的重试间隔 |

本方案使用显式 `esp_light_sleep_start()`，不依赖 ESP-IDF automatic Light-sleep。

## 7. 实机验收

1. 上电后不操作 60 秒，确认出现“进入轻睡眠”日志。
2. 再等待 60 秒，确认日志出现“内部 Timer 唤醒已刷新屏幕”，且未到服务端截止时间时没有
   启动网络会话。
3. 到达服务端配置的整点后，确认日志出现“联网维护同步完成”，随后再次停网、刷新屏幕并
   进入 Light-sleep。
4. 断开服务端或 Wi-Fi，确认 Dashboard 同步失败后仍能安全停网，下一分钟继续重试。
5. 任意周期按左键或右键，确认网络和屏幕恢复、按键业务可继续使用，并重新等待 60 秒才入睡。
6. 临时移除或禁用 SD 卡，确认低功耗流程不因此进入 `BLOCKED`。
