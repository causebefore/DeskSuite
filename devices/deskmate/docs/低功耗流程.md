# DeskMate 低功耗停网与可配置维护源 Light-sleep 流程

> 当前状态：设备在 60 秒无按键活动后选择低功耗模式。运行中的番茄钟页只关闭 Wi-Fi，
> 保持 UI 和秒级刷新；其他页面进入 Light-sleep。当前默认启用 RTC INT 硬件连线测试模式：
> 左右键与 GPIO15 RTC INT 可唤醒，ESP32 内部 Timer 完全禁用。关闭测试宏后恢复原来的内部
> Timer 维护唤醒。低功耗流程不读写 SD 卡。

## 1. 当前边界

- Light-sleep 不复位芯片；唤醒后从 `esp_light_sleep_start()` 的下一条语句继续执行。
- 左键 GPIO18、右键 GPIO0 通过 EXT1 低电平唤醒。
- 普通模式中，ESP32 内部 Timer 是维护唤醒源，屏幕维护间隔默认 60 秒；Dashboard 截止或
  番茄钟单调 deadline 更近时缩短本轮间隔。番茄钟间隔计算不依赖系统 UTC。
- RTC INT 测试模式中，GPIO15 作为第三个 EXT1 低电平唤醒源；ESP32 内部 Timer 不配置，
  RTC INT 唤醒不重置无活动窗口。软件不在睡前读取或判定 GPIO15 当前高低；唤醒后通过
  `rtc_service` 的 AF 消费结果确认中断已经处理。
- 网络停机与 Light-sleep 是两个独立步骤。`app_network_suspend_for_power_save()` 不要求 UI
  已停止；运行中的番茄钟页可以在 Network Manager 和 Wi-Fi Driver 停止后继续刷新。
- 完整 Light-sleep 仍对语音 Runtime、UI Runtime、显示传输和网络链路执行可逆 `stop/start`。
- 语音 `stop()` 只关闭新会话入口、停泊 AFE Task、关闭输入输出；Codec、AFE、模型、缓冲和
  Task 实例继续保留，Light-sleep 循环不调用 `deinit()`。
- 网络停止由 `app_network` 串行关闭产品 Timer、远端日志、Network Manager 和 Wi-Fi Driver；
  恢复只重启连接策略，需要联网维护时再同步等待 Dashboard 完成。
- 清醒态的 Dashboard 一次性 Timer 与 Light-sleep 联网维护共用服务端
  `next_refresh_at_utc`；本地失败退避只用于完整同步失败后的恢复，不参与正常刷新计划。
- 环境、按键扫描、RTC Service 和 SD 卡尚未增加独立低功耗生命周期；Button Service 保持
  RUNNING，不在睡前 `stop()`、唤醒后 `start()`。
- WakeNet 常驻监听启用时自动 Light-sleep 关闭，因为 CPU 睡眠时不能处理麦克风数据。

内部 Timer 和 EXT1 都是 ESP32 睡眠控制器的硬件唤醒源，不是 FreeRTOS 软件 Timer。CPU
进入 Light-sleep 后普通 Task 不运行；任一已启用来源命中后，睡眠控制器恢复 CPU，原 Task
继续执行。

## 2. 职责分层

| 层级 | 组件 | 当前职责 |
| --- | --- | --- |
| Application | `main/application/app_power_task.c` | 60 秒活动窗口、前台离线显示、语音/AFE 阻止条件、Dashboard/番茄钟截止聚合、RTC 告警消费确认、唤醒补算、语音/UI/网络顺序和失败终态 |
| Application | `main/application/app_pomodoro_task.c` | 单调阶段 deadline、前台秒级显示事实、睡眠后同步补算、完成 latch 和 Presenter 收敛 |
| Application | `main/application/app_voice.c` | Audio → AFE → Voice 的唯一产品生命周期、按键入口和实时语音租约 |
| Application | `main/application/app_network_task.c` | 与 UI/Light-sleep 解耦的网络可逆暂停/恢复、同步维护回执及最近 `next_refresh_at_utc` |
| UI Runtime | `main/ui` | 可逆停止、Presenter 重同步和恢复刷新 |
| Graphics | `components/graphics/ui_platform` | 停止 LVGL/显示提交；恢复时同步完成一次完整显示传输 |
| Device | `components/device/device_power` | 转发一次同步睡眠事务和语义化唤醒事实，不拥有周期策略 |
| BSP | `components/bsp/src/bsp_power.c` | 按编译配置互斥选择内部 Timer 或 RTC INT 维护源，进入睡眠并锁存 EXT1/Timer 唤醒来源 |

SD 卡仍可被其他产品能力使用，但不再是 `app_power` 的依赖，也不再决定设备能否睡眠。

## 3. 主流程

```text
按键活动
    → app_power_notify_activity()
    → 重新开始 60 秒活动窗口

活动窗口到期
    → 读取 app_voice 状态
    → 检查活动会话 / AFE drain / 音频输入输出 / OTA / 网络租约
    → app_pomodoro_requires_live_display()？
        → true：
            → app_network_suspend_for_power_save()
            → 进入 APP_POWER_STATE_OFFLINE_DISPLAY
            → UI 与番茄钟一秒 Timer 保持运行
        → false：
            → app_voice_stop(3000 ms)
            → ui_runtime_stop()
            → app_network_suspend_for_power_save()
            → Device / BSP 配置左右键 EXT1
              + 普通模式：min(60 秒, 距服务端截止时间, 距番茄钟阶段截止) 内部 Timer
              + RTC INT 测试模式：GPIO15 EXT1，完全不启用内部 Timer
            → esp_light_sleep_start()
```

语音 `stop()` 不取消当前会话。录音、上传、播放、AFE drain、输入输出活动或语音租约会暂时
阻止本轮睡眠，并沿用 10 秒重试；会话自然结束后再进入下一轮准备。

UI `stop()` 关闭业务入口、停止 LVGL tick 与新帧提交、等待显示 DMA 静止，并保留控件树、
字体、绘制缓冲、显示 Task、SPI 和面板控制器。

网络 `stop()` 停止 Dashboard/OTA/重连/校时 Timer 和远端日志，再同步停止 Network Manager
及 Wi-Fi Driver。它不停止 UI，也不直接进入 Light-sleep。任一步失败都会回滚到清醒态，不会
在网络状态不明时继续低功耗流程。

## 4. 离线显示与三类唤醒

### 4.1 番茄钟前台离线显示

```text
APP_POWER_STATE_OFFLINE_DISPLAY
    → UI Runtime 与番茄钟一秒 Timer 持续运行
    → Network Manager、Wi-Fi Driver 和网络产品 Timer 保持停止
    → Dashboard 截止到达？
        → 是：临时恢复网络 → 同步 Dashboard → 再次停网
    → 用户按键、阶段完成或离开运行中的番茄钟页？
        → 是：恢复网络策略 → 返回 AWAKE
```

离线显示不调用 `device_power_enter_light_sleep()`，因此 `mm:ss` 可以连续更新。按键事实会先调用
`app_power_notify_activity()`，唤醒 Power Task 恢复网络；番茄钟自然完成同样更新活动代次，
恢复网络并进入正常 60 秒清醒窗口。暂停或 `DONE` 不需要秒级变化，允许按普通策略进入完整
Light-sleep。

### 4.2 Timer 维护唤醒

```text
内部 Timer 到期
    → 锁存 APP_POWER_WAKEUP_TIMER
    → app_pomodoro_reconcile_after_wakeup()
        → 阶段完成：先更新 Presenter，记为活动并恢复正常清醒窗口
        → 尚未完成：重新调度番茄钟 one-shot Timer
    → 语音 Runtime 保持 STOPPED
    → 可信 UTC >= next_refresh_at_utc？
        → 是：恢复网络 → 同步 Dashboard → 保存新截止时间 → 再次停网
        → 否：网络保持停止
    → ui_runtime_start()
    → 从 Presenter 重新读取状态栏和当前页面
    → 同步提交完整刷新并等待显示 DMA 完成
    → timer_refresh_count++
    → 检查停止请求、新按键活动和产品阻止条件
    → 条件仍允许时再次 ui_runtime_stop()
    → 重新配置下一次屏幕/联网维护 Timer 并继续 Light-sleep
```

普通 Timer 维护唤醒不会修改 `s_last_activity_us`，因此不会人为开启新的 60 秒交互窗口；
番茄钟阶段自然完成是例外，它会更新活动代次、恢复网络/语音/UI 并开启新的 60 秒清醒窗口。
没有
成功解析截止时间或系统 UTC 尚不可信时按“已到期”处理，借助本次联网同步取得可信时间和新
截止时间。Dashboard 同步失败保留旧截止时间，安全停网后在下一分钟重试。若刷新期间出现
按键活动，先恢复网络，再启动语音 Runtime，最后确保 UI 已启动并返回正常清醒流程。纯维护
窗口内语音始终保持 `STOPPED`。

### 4.3 RTC INT 测试唤醒

启用 `CONFIG_DESKMATE_RTC_INT_WAKE_TEST_ENABLED` 后，BSP 将 GPIO15 加入 EXT1 ANY_LOW 掩码，
并跳过 `esp_sleep_enable_timer_wakeup()`；左右键仍可提前唤醒。RTC 芯片必须已安排告警，
否则在没有按键输入时设备会一直睡眠，这正是无 Timer 兜底测试的预期行为。

```text
RTC INT GPIO15 拉低
    → EXT1 唤醒并锁存 rtc_alarm=true
    → APP_POWER_WAKEUP_RTC_ALARM
    → rtc_service_request_check()
    → RTC Service 读取并清除 AF
    → alarm_count 相对睡前快照变化，确认本轮告警已消费
    → 番茄钟补算、按需网络维护、UI 完整刷新
    → rtc_alarm_refresh_count++
    → 再次进入 RTC INT + 双按键 Light-sleep
```

关键日志为 `RTC INT=是`、`Timer=否`、`EXT1 状态=0x8000` 以及
`RTC INT 唤醒的告警消费已确认`、`RTC INT 唤醒已刷新屏幕`。其中 GPIO15 对应 EXT1 状态位
`1 << 15`，即 `0x8000`。如果只有左右键命中，EXT1 状态分别包含 GPIO18 或 GPIO0 对应位。
若 RTC Service 在覆盖 1、2、4 秒内部重试的有界时间内仍未确认告警消费，或测试模式下设备
报告睡眠源已经有效，Application 会恢复清醒 Runtime 并进入 `BLOCKED`，禁止每 10 秒重复
启停。该测试只验证软件是否收到了硬件唤醒事实，不替代电气层的上拉、波形和焊接质量确认。

### 4.4 左右键交互唤醒

左右键命中 EXT1 后，流程依次恢复网络连接策略、语音 Runtime、UI 并等待画面刷新完成，然后
增加 `success_count`、更新最后活动时间，重新开始 60 秒清醒窗口。若按键与维护源同时命中，
按键语义优先。

睡眠期间 CPU 不执行普通 GPIO ISR，不能依赖睡眠中的按键边沿在唤醒后重放。BSP 因此按值返回
EXT1 左右键事实，Application 在 UI 恢复后显式桥接：

```text
EXT1 左右键掩码
    → app_power 恢复网络 → app_voice_start() → 恢复 UI
    → button_service_request_light_sleep_wakeup_copy()
    → 持续按住：原 Device 状态机判定短按/长按
    → 快速释放：Button Service 重放一次短按
```

左右键事实可以同时提交；Button Service 将 EXT1 事实、GPIO 边沿和 Device 事件合并，同一实体键
最多产生一个产品事件。只有唤醒事实提交成功后，`app_power` 才增加 `success_count`。

GPIO0 是 ESP32-S3 启动配置引脚。Light-sleep 唤醒不发生复位，因此运行期可安全作为唤醒源；
上电或硬复位时仍不得一直按住右键。

## 5. 状态与错误

`app_power_get_status_copy()` 提供以下关键事实：

- `cycle_id`：每次物理 Light-sleep 尝试编号；
- `state` / `step`：当前主状态和显式步骤；`APP_POWER_STATE_OFFLINE_DISPLAY` 表示只停网、
  UI 仍在运行；
- `wakeup_source`：最近一次按键、RTC INT 或 Timer 唤醒来源；
- `success_count`：按键唤醒并恢复交互次数；
- `rtc_alarm_refresh_count`：RTC INT 唤醒并完成屏幕刷新次数；
- `timer_refresh_count`：Timer 唤醒并完成屏幕刷新次数；
- `primary_error`：睡眠、语音、UI 或网络停止主流程错误；
- `recovery_error`：网络、语音或 UI 恢复错误。

按键尚未释放、准备期间出现新活动，或 `app_voice_stop()` 因会话刚开始而返回
`ESP_ERR_INVALID_STATE`，都属于暂时取消；按网络、语音、UI 恢复后等待下一次机会。未知唤醒
来源、睡眠配置失败、语音/网络/UI 无法证明已停止或恢复会进入 `BLOCKED`，禁止继续自动睡眠。Dashboard
同步失败只保留旧数据并按分钟重试，不进入 `BLOCKED`。SD 卡错误不会进入
这条错误链。`button_service_request_light_sleep_wakeup_copy()` 提交失败同样属于恢复错误，
保存在 `recovery_error` 后进入 `BLOCKED`，禁止继续自动睡眠。

RTC INT 测试模式下，唤醒后的 AF 消费确认超时、RTC Service 不在运行态，或
`esp_light_sleep_start()` 因唤醒源已经有效而拒绝睡眠，都属于测试链路不可靠并进入
`BLOCKED`；这些错误不会沿用普通暂时阻止条件的 10 秒重试。

完成 100 次实机 Light Sleep 验收前，不增加 Button Service 睡前 `stop()` / 醒后
`start()`。该生命周期调整保留为后续独立阶段。

## 6. 配置

| Kconfig | 默认值 | 含义 |
| --- | --- | --- |
| `DESKMATE_LIGHT_SLEEP_ENABLED` | `y` | 启用离线显示策略与 Light-sleep 编排 |
| `DESKMATE_RTC_INT_WAKE_TEST_ENABLED` | `y` | RTC INT GPIO15 独占维护唤醒测试；启用时内部 Timer 完全禁用 |
| `DESKMATE_LIGHT_SLEEP_IDLE_TIMEOUT_SEC` | `60` | 最后一次按键活动后的清醒窗口 |
| `DESKMATE_LIGHT_SLEEP_REFRESH_INTERVAL_SEC` | `60` | 普通模式的 Timer 维护间隔；RTC INT 测试模式保留但不使用 |
| `DESKMATE_LIGHT_SLEEP_RETRY_DELAY_MS` | `10000` | 暂时不可睡眠时的重试间隔 |

`sdkconfig.defaults` 当前显式打开 RTC INT 测试。测试结束后把
`CONFIG_DESKMATE_RTC_INT_WAKE_TEST_ENABLED` 改为 `n` 即可恢复内部 Timer，不需要修改代码。
关闭 `DESKMATE_LIGHT_SLEEP_ENABLED` 后 Power Task 不启动，离线显示停网也不会执行。完整睡眠
使用显式 `esp_light_sleep_start()`，不依赖 ESP-IDF automatic Light-sleep。

## 7. 实机验收

1. 在番茄钟页启动计时，等待 60 秒，确认日志出现“番茄钟前台进入离线显示”，Wi-Fi 关闭且
   `mm:ss` 仍每秒更新；确认没有进入 Light-sleep。
2. 短按离开番茄钟页，确认网络策略立即恢复；再次空闲 60 秒后，语音、UI、网络依次停止并
   进入 Light-sleep。
3. 暂停番茄钟并等待 60 秒，确认允许进入 Light-sleep；恢复计时并停留在番茄钟页后重新进入
   离线显示。
4. 在离线显示期间到达 Dashboard 截止，确认临时联网同步、保存新截止后再次关闭 Wi-Fi，UI
   全程保持运行。
5. RTC INT 测试模式下等待 RTC 告警，确认日志依次出现 `RTC INT=是`、`Timer=否`、
   `EXT1 状态=0x8000`、“RTC INT 唤醒的告警消费已确认”和“RTC INT 唤醒已刷新屏幕”；
   整个过程不应出现内部 Timer 唤醒，也不应出现睡眠失败后的 Runtime 周期性启停。
6. 到达服务端配置的整点后，确认日志出现“联网维护同步完成”，随后再次停网、刷新屏幕并
   进入 Light-sleep。
7. 断开服务端或 Wi-Fi，确认 Dashboard 同步失败后仍能安全停网；下一次 RTC 告警到达时继续
   重试。
8. 任意周期按左键或右键，确认按网络、语音、UI 的顺序恢复后才重放按键；进入语音页长按
   右键可开始下一轮，并重新等待 60 秒才入睡。
9. 录音、上传或播放期间让活动窗口到期，确认不会取消会话；终态后下一次重试可入睡。
10. 第一次语音后确认 `aps_feed/aps_fetch` 常驻但阻塞，连续会话不会增加 Task 数量。
11. 连续执行 100 次“按键语音 → 空闲 → 睡眠 → 按键唤醒”，确认 Task/堆不持续增长，且无
   AFE 残留和 I2S 恢复失败。
12. 临时移除或禁用 SD 卡，确认低功耗流程不因此进入 `BLOCKED`。
