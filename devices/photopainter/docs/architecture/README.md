## 规范用语

- **必须（MUST）**：新增或修改代码必须遵守；除非用户明确批准例外。
- **应当（SHOULD）**：默认做法；偏离时必须说明具体理由。
- **可以（MAY）**：允许但不要求，不得为了满足形式提前创建抽象。

当前实现、旧备忘或审查记录与本规范冲突时，以本规范作为目标；不得根据当前代码反向推断出新的架构规则。发现偏移时应单独报告或迁移，不能静默修改规范。

## 尚未确认的边界

以下内容不得由 AI 自行补全为规则，后续需要继续讨论：

1. 除产品规范中已经确认的具体流程外，各组件精确的启动、停止顺序及部分启动失败时的回滚表。
2. NVS 初始化失败、数据损坏、版本迁移和恢复默认值的产品策略。
3. 各命令队列分别采用拒绝、覆盖或合并中的哪一种满队列策略。
4. 各 Task 的实际优先级、栈大小、停止方式及是否需要核亲和性。
5. 单元测试、实机测试、静态检查和架构依赖检查的最低验收门槛。
6. 异步组件是否允许多个未完成请求，以及请求关联、取消、停止和结果队列满时的处理语义。
7. 除 Network Manager、显示服务等已经明确同步停止契约的组件外，其他异步组件的 `stop()` 是否等待 Task 完全退出，以及 `stop/deinit` 是否允许幂等例外；未声明例外时仍按非法状态返回 `ESP_ERR_INVALID_STATE`。
8. SD 在启动成功后发生运行期 I/O 故障时的恢复、重试、卸载和最终降级策略。
