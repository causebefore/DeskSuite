# `photo_playback_app`

> 串行拥有照片导航、集合收敛、模态 ASCII 状态页和全部运行期按键语义。

## 1. 定位与职责

- 层级：Application
- 状态所有者：当前页面、已收敛集合代数、导航队列、模态捕获和显示控制队列
- 执行资源：一个 FreeRTOS Task、导航 Queue、显示控制 Queue、同步控制信号量

负责启动页策略、左右循环导航、新集合收敛、确认键长按内容刷新、左键三秒固件检查请求、
物理中键三秒配网请求，
以及固件流程使用的模态状态页。所有照片和 ASCII 页面都在同一 Task 中串行呈现，显示期间停止
按键扫描，完成后再恢复。不负责联网、OTA 检查、安装、深睡策略或状态页业务文案。

## 2. 主要流程

```text
照片导航或集合提交
    → 选择并复制目标页
    → 停止按键扫描
    → display_present_service 同步全刷
    → 恢复按键并发布集合/活动事实

电源管理 App 提交状态页
    → 复制最多 4 行 ASCII 文本到控制 Queue
    → 播放 Task 清白、逐行绘制并只全刷一次
    → 发布 MODAL_PAGE

电源管理 App 请求恢复
    → 优先复制最近成功页，否则选择活动集合默认页
    → 同一 Task 物理全刷
    → 发布 IDLE
```

## 3. 按键与模态规则

- 普通状态：左/右单击上一张或下一张；确认键长按提交完整内容刷新；左键持续至少 3 秒并
  松开后提交一次固件检查请求；物理中键持续至少 3 秒并松开后提交配网请求。
- `begin_modal_borrow()` 启用后，左键单击提交取消/返回，确认键单击提交确认动作；右键及所有
  长按均被消费，不进入普通导航或刷新语义。
- `begin_provisioning_modal()` 用于 `NO NETWORK`/`NO SERVER`：只接受中键三秒配网，消费其他
  按键；普通点击不产生用户活动。OTA 模态不启用该能力。
- 模态期间到达的新集合提交会延后；`end_modal()` 恢复普通按键后重新提交集合收敛通知。
- 非 `IDLE` 或模态捕获期间，外部导航请求会被拒绝并累加计数。

## 4. 生命周期与故障

- `init(config) → start → stop → deinit`，成功停止后允许再次启动。
- Task 优先级 3、栈 8192 字节、不绑核。
- 状态页和照片恢复命令同步等待最多 40 秒，覆盖一次已开始的全刷。
- 呈现失败保留最近成功照片副本；按键恢复失败进入 `ERROR`。
- 停止清理失败进入 `CLEANUP_FAILED` 并拒绝反初始化。
- 启动时可保留墨水屏断电画面；若一次性恢复标记存在，装配层要求物理呈现当前页面，并只在
  成功后清除标记。

## 5. 依赖与验证

调用 `button_service`、`display_collection_service` 和 `display_present_service`。应验证普通左右
循环、三种左键时长、确认键长按、状态页单次全刷、模态按键屏蔽、当前/默认页恢复、集合延后、
显示失败和停止超时。公共 API 保持 C ABI，控制 Queue 只保存拥有的文本副本。
