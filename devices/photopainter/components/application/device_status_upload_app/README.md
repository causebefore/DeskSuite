# `device_status_upload_app`

> 设备状态上传 Application 在上传前按需采样环境，把联合快照转换为服务端契约并同步上传。

## 1. 定位

- 层级：Application
- 触发方：`content_refresh_app` 在网络获得可用 IPv4 后调用
- 主要输出：服务端按设备保存的最近温湿度与电池状态

## 2. 职责边界

负责：

- 触发 `environment_service` 完成一次新的联合采样，再复制该次结果。
- 要求最近一次电池采样成功；温湿度失败时明确降级为只上传电池。
- 把 Service 快照转换为 `device_status_protocol` 的上传结构并同步提交。

不负责：

- 决定环境周期采样；当前链路只在确实需要上传时采样一次。
- 启动、停止或恢复网络会话。
- 周期调度、失败重试、显示刷新和休眠策略。

## 3. 主要流程

```text
网络可用
    ↓
按需采样温湿度与电池 → 复制 environment_service 快照
    ├─ 最近电池采样失败 → 返回错误，不上传旧电池值
    └─ 电池有效 → 温湿度有效则一并携带，否则省略 environment
                         ↓
              PUT /api/v1/device/status
```

## 4. 依赖关系

| 方向 | 组件 | 用途 |
| --- | --- | --- |
| 调用 | `environment_service` | 上传前按需采样并复制本次联合结果 |
| 调用 | `protocols` | 同步编码并上传设备状态 |
| 被调用 | `content_refresh_app` | 每轮网络可用后的单次状态上传 |

## 5. 公共接口

公共头文件：[`include/device_status_upload_app.h`](include/device_status_upload_app.h)

| API | 同步性 | 作用与完成语义 |
| --- | --- | --- |
| `device_status_upload_app_upload()` | 同步 | 返回 `ESP_OK` 时服务端已返回 2xx |

配置中的字符串只在调用期间借用；函数返回后不保存指针。`device_id` 为空时由服务端使用默认
设备 ID。

## 6. 状态、生命周期与并发

- 生命周期：无独立生命周期；每次调用都是有界的同步用例。
- 状态所有者：本组件不保存可变状态。
- Task：本组件不创建 Task，由调用方 Task 执行同步采样、快照读取和 HTTP 请求。
- 回调/队列：无。

## 7. 故障与恢复

- 环境 Service 不可用或本次电池采样失败时直接返回对应错误，不用旧值刷新服务端接收时间。
- 温湿度最近采样失败不是整次上传失败，服务端页面将室内温湿度显示为 `--`。
- 参数、采样、快照、HTTP 和鉴权错误均保留原始 `esp_err_t`；何时重试、跳过或结束网络会话
  由上层产品流程决定。

## 8. 配置与文件

- 服务地址和 Token 来自当前持久化网络配置。
- HTTP 超时由调用方按当前网络会话传入。
- 持久化格式：无。

## 9. 验证

- 静态检查：确认采样发生在上传转换前，且没有直接依赖 Device、BSP、Driver 或网络管理器。
- 构建：用户明确要求时，在 DeskSuite 根目录执行 `& .\ds.ps1 build photopainter`。
- 实机：检查完整状态、温湿度降级、无效电池和服务端拒绝四条路径。
- 已知缺口：当前没有自动化测试；周期上传和显示同步时机尚未在本组件内定义。
